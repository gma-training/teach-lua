Lua for Configs Lesson 02

Numbers: one type, or two?

The first place your two configs genuinely disagree. A number means something different in Neovim than it does in Hyprland — and the gap is a real bug source, not a footnote.

Everything in Lesson 01 — local, nil, truthiness — behaves identically in every Lua. Numbers are where that stops. Here Neovim (LuaJIT, Lua 5.1) and Hyprland (Lua 5.4) diverge, and code you write comfortably in one can throw a syntax error or print something unexpected in the other. This lesson is the whole divergence, small enough to hold in your head.

Two models, one word

In Neovim 5.1 there is one number type: every number is a 64-bit float. 1 and 1.0 are literally the same value.

In Hyprland 5.4 a number has two subtypes, integer and float. A literal with a dot or exponent is a float; otherwise it's an integer. Both still report type(x) == "number" — you tell them apart with math.type, which doesn't even exist in Neovim.

-- Hyprland 5.4
print(math.type(3))     --> integer
print(math.type(3.0))   --> float
-- Neovim 5.1: math.type is nil; calling it errors
You already know the 5.4 model: it's Python 3. Integers and floats are distinct, and (next section) / vs // work exactly as they do in Python. The 5.1 model — a single float type, no integer, no // — is the unfamiliar one; think of it as "everything is a Python float."

Division is where it bites

Two operators, and only one of them exists everywhere:

ExpressionNeovim 5.1Hyprland 5.4
10 / 255.0 — / is always float
7 // 2syntax error3 — floor division
2 ^ 388.0 — ^ is always float
// is a Lua 5.3+ feature. LuaJIT never added it, so writing 7 // 2 in a Neovim config is a parse error — the file won't load at all. This is the classic trap: you learn // from a Hyprland snippet, reach for it in init.lua, and Neovim refuses to start.

In a Hyprland config, what does print(10 / 2) display?

In 5.4, / is always float division, so 10 / 2 is the float 5.0, printed with its .0. In Neovim the same line prints 5, because there are no integers to distinguish it from.

Printing gives the subtype away

Because 5.4 tracks the subtype, it prints floats with a trailing .0 so you can see what you have. 5.1 has nothing to distinguish, so it doesn't.

print(1.0)
-- Neovim 5.1  --> 1
-- Hyprland 5.4 --> 1.0

Useful signal when debugging: if a Hyprland value prints 1.0 where you expected 1, some arithmetic upstream turned it into a float — often a stray /.

Predict each result, then reveal.

-- what happens in each config?
local cols = 7 // 2

Hyprland 5.4: cols becomes 3 (floor division).

Neovim 5.1: the file fails to parse — // isn't a valid operator. The portable rewrite that works in both is local cols = math.floor(7 / 2), which is also 3.

Writing arithmetic that survives both

A few habits keep config math portable:

  • Floor division: write math.floor(a / b), never a // b, unless the file is Hyprland-only.
  • Bitwise: 5.4 has native & | ~ << >>; 5.1 has none — LuaJIT ships a bit library (bit.band(5, 3)). Different code entirely, so keep bit-twiddling out of shared logic.
  • Don't lean on subtype: guard any math.type use behind if math.type then, since it's absent on 5.1.

Which floor-division approach works unchanged in both Neovim and Hyprland?

math.floor(a / b) works everywhere: / exists in both, and math.floor is in the standard library of every Lua. // is 5.4-only; bit.band is a Neovim-only library and isn't division; plain / doesn't floor.

This whole lesson is the divergence. Anchor it: Hyprland 5.4 numbers = Python 3 (/, //, int vs float). Neovim 5.1 = one float type, no //. When in doubt, write to the 5.1 floor (no //, no native bitwise) and it runs on both.
Primary: Lua 5.4 Reference Manual §3.4.3 "Coercions and Conversions" / Arithmetic for the 5.4 rules, and LuaJIT Extensions (see "not backported": floor division, bit operators) for exactly what Neovim lacks.

Lua for Configs Lesson 05

Strings & the : method call

Joining is .. not +, methods hang off a colon, indices start at 1 and include both ends, and # counts bytes. Five habits and every string line in a config reads cleanly.

Strings are the other half of a config — paths, colours like "#111", keymap names, formatted messages. Lua's string model is small but its spellings differ from all three languages you know. This lesson is those differences, and the one piece of genuinely new syntax the course has been deferring: the : method call.

Join with .., and mind the coercion

.. is concatenation; + is always arithmetic (Lesson 01 flagged this). The twist: Lua coerces between strings and numbers automatically. Concatenation turns a number into its text; arithmetic turns a numeric string into a number.

print("width=" .. 80)   --> width=80   (number coerced to string)
print("10" + 5)        --> 15         (numeric string coerced to number!)
That second line is the trap. Python raises a TypeError; JavaScript makes "10" + 5 the string "105" because its + is overloaded for concatenation. Lua does neither: + is only ever arithmetic, so it coerces "10" to a number and gives 15. Keep the two operators straight — .. to join, + to add — and never rely on the string-to-number coercion; make conversions explicit with tonumber/tostring.

Methods via : — the one new syntax

Every string carries the string library as its method table, so you can call its functions directly on any string value. s:upper() is pure sugar for string.upper(s) — the colon passes s as the hidden first argument.

local s = "hypr"
print(s:upper())            --> HYPR
print(s:sub(1, 2))          --> hy      (same as string.sub(s, 1, 2))
print(string.upper(s))      --> HYPR    (the un-sugared form)
This looks like Python/Ruby method calls (s.upper()), and reads the same way — but note the colon. In Lua, s:upper() passes self; s.upper() with a dot would look the method up but pass nothing, so it misbehaves. Rule: call string (and later, table) methods with :. You'll meet the same :-defines-and-passes-self rule again when configs define their own methods.

What is s:lower() exactly equivalent to?

The colon is sugar that passes the receiver as the first argument, so s:lower() is string.lower(s). The dotted s.lower() would pass no argument, and string.lower() with none errors.

Indices start at 1, include both ends, count from the end

String positions follow the same 1-based rule as tables (Lesson 03). string.sub(s, i, j) returns characters i through j inclusive, and negative positions count back from the end.

local s = "hyprland"
print(s:sub(1, 4))    --> hypr   (positions 1..4, both included)
print(s:sub(-4))      --> land   (last 4 characters)
Very different from Python slicing s[0:4], which is 0-based and excludes the end. Lua's sub is 1-based and includes it — the same inclusive convention as the numeric for (Lesson 04). The negative-index shorthand does match Python's s[-4:], which is a handy point of overlap.

# counts bytes, not characters

#s gives the string's length in bytes. For plain ASCII that equals the character count, but Lua strings are raw byte sequences with no encoding awareness, so a multibyte UTF-8 character counts as several.

print(#"hypr")    --> 4
print(#"café")    --> 5   (the é is two UTF-8 bytes)
Counting actual characters isn't built into the language the same way across versions. Lua 5.4 ships a utf8 library — utf8.len("café") returns 4, and utf8.char/utf8.charpattern help you walk codepoints. Lua 5.1 has no utf8 library at all (nor does the LuaJIT runtime), so there # and byte iteration are all you get out of the box. Configs are mostly ASCII, so this rarely bites — but don't reach for utf8.* in code that must load on 5.1.

Writing literals: quotes and long brackets

Single and double quotes are interchangeable and both honour escapes (\n, \t, \\). For multiline text, long brackets [[ … ]] take everything verbatim — no escape processing — and drop a newline immediately after the opening bracket.

local a = 'single'            -- identical kind to "double"
local block = [[
line one
line two
]]                            -- a multiline string; \n here is literal backslash-n
Long brackets are Lua's triple-quoted string (Python """…""") or JS template literal — minus interpolation. There's no ${…} / f"…" in Lua; to build a string from parts you use .. or string.format (next section). If the text itself contains ]], bump the level: [==[ … ]==].

string.format — printf, with a 5.4 catch

For anything beyond simple joins, string.format follows C's printf: %s for a string, %d for an integer, %x for hex, %02d to pad. It's the clean way to assemble config values.

print(string.format("[%s] width=%d", "hypr", 80))   --> [hypr] width=80
%d reconnects to Lesson 02. In Lua 5.4, %d demands a value with an integer representation: string.format("%d", 3.0) is fine (3.0 is a whole number), but string.format("%d", 3.5) errors — "number has no integer representation." In Lua 5.1, where every number is a float, %d simply truncates, so string.format("%d", 3.5) quietly yields "3". If a value might be fractional, round it explicitly (math.floor) before %d so both versions agree.

local s = "hyprland"

s:sub(-4) → land. A negative start counts from the end; with no second index it runs to the end of the string.

#s → 8. Eight ASCII bytes, so eight here — bytes and characters coincide because it's all ASCII.

Putting it together

The five habits in one config-shaped snippet — coercing join, a : method, and format:

local name = "hypr"
local file = name .. 54 .. ".conf"              --> hypr54.conf  (number coerced)
print(file:upper())                            --> HYPR54.CONF
print(string.format("loading %s (%d bytes)", file, #file))  --> loading hypr54.conf (11 bytes)
Primary: Lua 5.4 Reference Manual §6.4 "String Manipulation" for sub/format and the 1-based positions, plus §6.5 "UTF-8 Support" for the 5.4-only utf8 library.

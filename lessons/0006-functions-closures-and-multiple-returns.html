Lua for Configs Lesson 06

Functions, closures & multiple returns

Functions are ordinary values, they can return several values at once, and the rules for how those values get truncated or padded are the only real surprises here.

You've written closures in three languages, so the mechanics aren't new — but two Lua traits are: a function can return more than one value (not a tuple — genuinely several), and Lua silently adjusts value lists to fit. Get those and the callback tables, factories, and require lines in a config stop surprising you.

Functions are first-class values

A function is a value like any other: store it in a local, a table field, pass it as an argument. The named forms are sugar for an assignment.

local function save() … end          -- sugar, and visible to itself (recursion)
local save = function() … end       -- same value; but name not in scope inside yet

local handlers = {                     -- functions living in a table — the config idiom
  save = function() … end,
  quit = function() … end,
}
First-class functions work as in Python, Ruby, and JavaScript — no surprise. One fine point: local function save() declares the name before the body, so the function can call itself; the desugared local save = function() does not, so a recursive reference inside would hit an earlier/global save. Reach for local function when it recurses.

Multiple return values — the big feature

A Lua function can return several values, and you assign them positionally. Too few names on the left? The extras are dropped. Too many? The surplus become nil.

local function bounds() return 1, 80 end
local lo, hi = bounds()      --> lo=1, hi=80
local a, b, c = bounds()    --> a=1, b=80, c=nil   (padded)
local only = bounds()       --> only=1             (rest dropped)
This is not Python's "return a tuple." Python hands back one object you can store in one variable; Lua returns a genuine list of values that you cannot bottle up in a single variable — assign them to several names, or they're lost. Ruby (a, b = meth) and JS array destructuring are closer, but even they wrap a real object; Lua's multiple values are ephemeral.

How value lists get adjusted

The surprise is where a call keeps all its values. A call expands to all its results only in the last position of a list. Anywhere else — or wrapped in parentheses — it's truncated to exactly one.

local function f() return 1, 2 end
print(10, f())     --> 10  1  2   (f is last: expands)
print(f(), 10)     --> 1  10      (f not last: truncated to 1)
print((f()))      --> 1          (parentheses force exactly one)
Two habits fall out of this. Wrapping a call in parentheses, (f()), is the deliberate way to say "just the first value." And putting a multi-value call anywhere but last silently discards its tail — a real bug when you write t = { f(), other } expecting all of f's results in the table. If you need them mid-list, capture into locals first.

Given local function f() return 1, 2 end, what is z after local x, y, z = f()?

The left side asks for three values but f supplies two, so the extra name is padded with nil — never an error, never a repeat. This is the same "missing means nil" rule from Lesson 01.

Varargs: ...

A trailing ... in the parameter list collects any extra arguments. Inside, ... is itself a value list — pack it into a table with {...}, or count with select("#", ...).

local function log(level, ...)
  local args = {...}                 -- the extras as a sequence
  print(level, select("#", ...))    -- count, counts trailing nils too
end
Lua 5.4 offers table.pack(...), which returns a table with an .n field holding the true count (so it survives trailing nils that {...} and # would miscount). Lua 5.1 has no table.pack — use select("#", ...), which exists in both, when the count matters. (And recall Lesson 03: to spread a packed table back out it's unpack on 5.1, table.unpack on 5.4.)

Closures capture by reference

An inner function sees and keeps the locals ("upvalues") of the enclosing scope — captured live, not copied. Standard closure behaviour. The Lua-specific nicety is the loop: each iteration of a for makes a fresh loop variable, so closures created in a loop each capture their own value.

local fns = {}
for i = 1, 3 do fns[i] = function() return i end end
print(fns[1](), fns[2](), fns[3]())   --> 1  2  3
This is a place Lua tracks JavaScript's let, not Python. In JS with let i each iteration is a fresh binding and you get 1 2 3 — exactly Lua. With old var i, all three closures shared one variable and printed 3 3 3. Python has that same late-binding trap (all closures see the final i). Lua spares you it: the loop variable is fresh per iteration, so your JS-let instinct is the right one here.

What does print((f())) show when f returns 1, 2?

Wrapping a call in parentheses forces it to exactly one result — the first — so only 1 reaches print. Without the parens and in last position, print(f()) would show 1 2.

Call sugar you'll see everywhere

Two shorthands appear constantly in real configs. A call with a single string or single table literal may drop the parentheses. And the : from Lesson 05 also defines methods, quietly adding a self parameter.

require "socket"          -- same as require("socket")
setup { width = 80 }        -- same as setup({ width = 80 }) — the config idiom

function obj:greet(msg) … end   -- defines obj.greet(self, msg); self is implicit
The f{ … } form is why config files read as plugin.setup { … } with no visible parentheses — it's an ordinary call taking one table. Nothing magic: strip it back to setup({ … }) in your head. And obj:greet(m) to call, obj:greet to define, both thread self — the mirror of the string methods you already use.

Predict the printed values, then reveal.

local function f() return 1, 2 end
print(f(), f())

1  1  2. The first f() is not in the last position, so it's truncated to a single value, 1. The second f() is last, so it expands to all its results, 1 and 2. Three values reach print: 1, 1, 2.

This holds identically on 5.1 and 5.4 — value-list adjustment is core language, not a version feature.

Putting it together

A closure factory — first-class return, a captured upvalue, multiple calls — the shape a config uses for toggles and counters:

local function make_toggler(state)
  return function()          -- captures `state` by reference
    state = not state
    return state
  end
end

local toggle = make_toggler(false)
print(toggle(), toggle())     --> true  false
Primary: Lua 5.4 Reference Manual §3.4.11 "Function Definitions" for the call/return and adjustment rules, and Programming in Lua §6 "More about Functions" for closures and varargs in the author's words.

Loops

FormNotes
for i = 1, n do … endinclusive of n (unlike Python range); optional 3rd arg is the step, e.g. 10, 1, -1
for i, v in ipairs(t) doarray part, keys 1.., in order, stops at first nil
for k, v in pairs(t) doevery key (array + hash), order unspecified
while cond do … endtests before the body
repeat … until condtests after (runs ≥ once); cond is the exit test and can see body locals

The two iterator traps

-- pairs has NO order — sort keys yourself when it matters:
local keys = {}
for k in pairs(t) do keys[#keys + 1] = k end
table.sort(keys)
for _, k in ipairs(keys) do print(k, t[k]) end

-- ipairs stops at a hole: keep sequences dense (Lesson 03).
Mostly version-agnostic. One visible split: in Lua 5.4 an all-integer numeric for gives an integer counter (so for i = 1, #t yields integer indices; a float bound makes it float, printing 1.0 2.0 …). In Lua 5.1 there are no subtypes, so the counter is always a float that prints as 1 2 …. Keep loop bounds integer literals or #t for table indexing. Branching, pairs/ipairs, and the loop keywords are identical across versions.

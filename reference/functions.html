Functions & closures

First-class values, several returns at once, and the adjustment rules that bite.

Defining

local function f(a, b) … end     -- name visible inside (recursion-safe)
local f = function(a, b) … end   -- name NOT visible in its own body yet
function obj:m(x) … end          -- defines obj.m(self, x); self implicit
function f(...) local t = {...} end  -- varargs collected

Multiple returns & adjustment

ContextResult of a call returning 1, 2
local x, y = f()x=1, y=2
local x, y, z = f()z=nil — surplus names padded
local x = f()x=1 — tail dropped
print(10, f())10 1 2 — last position expands
print(f(), 10)1 10 — non-last truncates to 1
print((f()))1 — parens force exactly one

Closures

-- fresh loop variable per iteration → distinct captures:
for i = 1, 3 do fns[i] = function() return i end end   --> 1, 2, 3
Mostly version-agnostic. First-class functions, multiple returns, adjustment, and closures are identical on 5.1 and 5.4. Only varargs packing differs: table.pack is 5.4-only; select("#", ...) is the portable count. Closure/loop model: Lua's fresh-per-iteration loop variable matches JavaScript let (not var, and not Python's late-binding capture).
